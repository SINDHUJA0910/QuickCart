# QuickCart — Android (Capacitor)

Ships the exact same PWA as `frontend/public` — no separate native codebase.
Capacitor wraps it in a WebView and gives it a real APK, an app icon, splash
screen, and native camera permission handling for barcode scanning.

## Why no `android/app/` native project is committed here

Capacitor's native Android project (`android/app/src/...`, Gradle files,
`AndroidManifest.xml`, etc.) is **generated**, not hand-written — it's
produced by `npx cap add android` from the Android SDK/Gradle toolchain on
your machine, and regenerated by `npx cap sync` whenever web assets or
plugins change. Committing a hand-built copy of that generated tree here
would immediately go stale and likely conflict with what your own toolchain
produces. What's committed instead is everything Capacitor needs to
generate it correctly: `capacitor.config.json` (points at `frontend/public`
as the web asset directory) and `package.json` (the exact plugin set this
app needs).

## Setup (one-time)

Requires Node.js, Android Studio, and the Android SDK installed.

```bash
cd android
npm install
npx cap add android      # generates the native project from capacitor.config.json
npx cap sync              # copies frontend/public into the native project + applies plugins
```

## Every time you change frontend/public

```bash
cd android
npx cap sync
```

## Running / building

```bash
npx cap open android      # opens the generated project in Android Studio — run from there for a device/emulator
# or, for a release APK from the command line:
npm run build-apk         # runs ./gradlew assembleRelease in the generated android/ project
```

## Camera permission for barcode scanning

The app's live barcode scanning (`frontend/public/app/shop.html`) uses the
browser-standard `getUserMedia` + `BarcodeDetector` APIs, which work
directly inside the Capacitor WebView on Android — no custom native
scanning code needed. `@capacitor/camera` is included as a dependency
specifically so its Android module's manifest merge adds the `CAMERA`
permission declaration automatically when you run `cap add android`; you
don't need to hand-edit `AndroidManifest.xml` for this.

If a runtime permission prompt doesn't appear on first scan on some device/
OS combinations, add an explicit runtime permission request using
`@capacitor/camera`'s `Camera.requestPermissions()` in `shop.html` before
calling `getUserMedia` — the plugin is already a dependency, this is a
few-line addition once you're testing on a real device where you can
observe the actual permission flow.

## App identity

- **App ID**: `com.quickcart.app` (set in `capacitor.config.json`) — this
  is what Google Play uses as the permanent package identifier. Change it
  before your first real release; it cannot be changed after publishing.
- **App icon / splash screen**: not included — generate with
  `npx @capacitor/assets generate` once you have real icon artwork, pointed
  at this config's `androidSplashResourceName` setting.
